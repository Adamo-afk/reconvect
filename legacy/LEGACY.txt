LEGACY CODE INVENTORY
=====================

This folder holds code that predates the Romanian COALITION-4 pipeline and
is no longer exercised by the active training flow. The active flow is:

    validate_timestep.py
        -> our_data/raw_data/{radar,lightning}_arrange.py
        -> our_data/{satellite,nwcsaf,opera}_data/pipeline_*.py
        -> our_data/lightning_data/read_kml_version2.py
        -> identify_patches.py / identify_lightning_periods.py
        -> regrid.py
        -> extract_patches.py
        -> extract_patch_seq_for_datasets.py        (Step 4.1)
        -> intersect_product_coverage.py            (Step 4.2)
        -> compute_normalization_stats.py           (Step 4.3)
        -> create_datasets.py
        -> train_models.py
        -> evaluate_coalition.py
        -> feature_importance_analysis.py

Files physically inside legacy/
-------------------------------

process_nwcsaf.py
    Standalone NWCSAF NetCDF reader, two top-level helpers:
      - extract_latlon_coordinates(input_nc_file)
      - read_and_scale_nwcsaf_variable(nc_filename, variable_name)
    Both transform from the MSG GEOS projection to WGS84 via pyproj.
    Equivalent (and broader) functionality lives inside regrid_nwcsaf() in
    regrid.py, which also reprojects onto the EPSG:31700 Romania grid and
    writes per-variable .npy files. The only remaining consumer of this
    module is the legacy c4dl/datasets/msgccs4.py reader (see below), which
    is itself dormant in the active pipeline.

Legacy code that still lives in its original location
-----------------------------------------------------
(Not moved here because it is interleaved with active modules — moving it
would require breaking imports inside c4dl/. Listed for documentation.)

c4dl/datasets/msgccs4.py
    Original MeteoSwiss MSG / NWCSAF dataset reader. Lazily imports
    `legacy/process_nwcsaf.py` inside its function bodies. Used only by
    c4dl/features/regions.py and c4dl/features/test_nc.py.

c4dl/features/test_nc.py
    Diagnostic / inspection utilities tied to the original MeteoSwiss test
    workflow. Imported by scripts/plot_predictions.py but not by any
    root-level pipeline script. The active replacement is
    data_statistics.py + the various summarize_*.py scripts.

c4dl/features/regions.py
    Patch-saving helpers (save_patches_radar, save_patches_lightning, ...)
    inherited from the original pipeline. The active extract_patches.py
    reimplements its own patch slicing + pooling on the regridded grids,
    so these helpers are unused at training time. A handful of legacy
    scripts (under scripts/) still pull from this module.

c4dl/datasets/msgccs4.py, c4dl/datasets/mchradar.py,
c4dl/datasets/mchlightning.py, c4dl/datasets/cosmonwp.py,
c4dl/datasets/swissdem.py, c4dl/datasets/solar.py,
c4dl/datasets/goesabi.py, c4dl/datasets/goesglm.py, c4dl/datasets/nexrad.py,
c4dl/datasets/ecmwfnwp.py, c4dl/datasets/asterdem.py
    Original per-source NetCDF readers from the MeteoSwiss / GOES forks.
    All replaced by the our_data/* pipelines + regrid.py + extract_patches
    in the Romanian pipeline.

scripts/
    Older MeteoSwiss-derived utility scripts. None are wired into the
    active validate_timestep -> train_models pipeline:
      - training_cscs.py            (original training entry point)
      - xi_grad_cam.py              (pre-merge Grad-CAM + Xi prototype)
      - generate_shaply_maps.py     (pre-merge SHAP prototype)
      - check_grad_cam.py
      - plot_predictions.py
      - plot_test_swiss_data.py
      - patch_stitching.py
      - plot_training.py
      - plots_lightning.py
      - mnist_gradient_vs_feature_maps.py
    Active replacements live at the project root:
      - feature_importance_analysis.py replaces xi_grad_cam +
        generate_shaply_maps + check_grad_cam (combined Grad-CAM + Xi +
        SHAP + classical Shapley analysis).
      - evaluate_coalition.py replaces plot_predictions /
        plot_test_swiss_data.
      - data_statistics.py + summarize_lightning_periods.py +
        summarize_raw_chunks.py + summarize_raw_data.py +
        summarize_opera_data.py replace plots_lightning + related
        per-product diagnostics.
      - train_models.py replaces training_cscs.

knowledge_distillation/
    Top-level duplicate of the c4dl/ tree from a separate research branch.
    Holds its own copies of every analysis / dataset / feature / model
    module. None of it is imported by anything in the active pipeline; a
    few legacy scripts (e.g. scripts/training_cscs.py) import from it for
    cross-branch comparisons.

Code that is NOT legacy (kept in c4dl/ because the active pipeline imports
it directly)
-------------------------------------------------------------------------

c4dl/projection.py
    GridProjection + romania_grid_area — used by regrid.py,
    identify_patches.py and read_kml_version2.py to define the EPSG:31700
    1536x768 target grid for Romania.

c4dl/ml/models/  (blocks.py, models.py, rnn.py, optimizers.py, ...)
    ResBlock / ConvGRU / model factories — used by train_models.py to
    build the COALITION recurrent-convolutional architecture dynamically
    from each dataset's metadata.json. Also imported by
    feature_importance_analysis.py for activation hooks.

c4dl/analysis/
    Loss / metric / Shapley helpers reused by evaluate_coalition.py and
    feature_importance_analysis.py.

c4dl/visualization/plots.py
    Plot helpers reused by evaluate_coalition.py.

c4dl/utils.py
    Generic numerical helpers (still imported by several modules).

Removing legacy code
--------------------
Anything in this file outside the "NOT legacy" section can be deleted at
any time without breaking the active pipeline; the dependencies are
contained. If you do decide to remove c4dl/datasets/msgccs4.py, remember
to delete legacy/process_nwcsaf.py at the same time (msgccs4 is the only
consumer left).
