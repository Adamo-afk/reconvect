LEGACY CODE INVENTORY
=====================

This folder holds code that predates the Romanian COALITION-4 pipeline and
is no longer exercised by the active training flow. The active flow is:

    validate_timestep.py
        -> our_data/raw_data/{radar,lightning}_arrange.py
        -> our_data/{satellite,nwcsaf,opera}_data/pipeline_*.py
        -> our_data/lightning_data/read_kml_version2.py
        -> identify_patches.py / identify_lightning_periods.py
        -> reproject.py
        -> extract_patches.py
        -> extract_patch_seq_for_datasets.py        (Step 4.1)
        -> intersect_product_coverage.py            (Step 4.2)
        -> compute_normalization_stats.py           (Step 4.3)
        -> create_datasets.py
        -> train_models.py
        -> evaluate_coalition.py
        -> feature_importance_analysis.py

Files physically inside legacy/
-------------------------------

process_nwcsaf.py
    Standalone NWCSAF NetCDF reader, two top-level helpers:
      - extract_latlon_coordinates(input_nc_file)
      - read_and_scale_nwcsaf_variable(nc_filename, variable_name)
    Both transform from the MSG GEOS projection to WGS84 via pyproj.
    Equivalent (and broader) functionality lives inside reproject_nwcsaf() in
    reproject.py, which also reprojects onto the EPSG:31700 Romania grid and
    writes per-variable .npy files. The only remaining consumer of this
    module is the legacy c4dl/datasets/msgccs4.py reader (see below), which
    is itself dormant in the active pipeline.

Legacy code that still lives in its original location
-----------------------------------------------------
(Not moved here because it is interleaved with active modules — moving it
would require breaking imports inside c4dl/. Listed for documentation.)

c4dl/datasets/msgccs4.py
    Original MeteoSwiss MSG / NWCSAF dataset reader. Lazily imports
    `legacy/process_nwcsaf.py` inside its function bodies. Used only by
    c4dl/features/regions.py and c4dl/features/test_nc.py.

c4dl/features/test_nc.py
    Diagnostic / inspection utilities tied to the original MeteoSwiss test
    workflow. Imported by scripts/plot_predictions.py but not by any
    root-level pipeline script. The active replacement is
    data_statistics.py + the various summarize_*.py scripts.

c4dl/features/regions.py
    Patch-saving helpers (save_patches_radar, save_patches_lightning, ...)
    inherited from the original pipeline. The active extract_patches.py
    reimplements its own patch slicing + pooling on the reprojected grids,
    so these helpers are unused at training time. A handful of legacy
    scripts (under scripts/) still pull from this module.

c4dl/datasets/msgccs4.py, c4dl/datasets/mchradar.py,
c4dl/datasets/mchlightning.py, c4dl/datasets/cosmonwp.py,
c4dl/datasets/swissdem.py, c4dl/datasets/solar.py,
c4dl/datasets/goesabi.py, c4dl/datasets/goesglm.py, c4dl/datasets/nexrad.py,
c4dl/datasets/ecmwfnwp.py, c4dl/datasets/asterdem.py
    Original per-source NetCDF readers from the MeteoSwiss / GOES forks.
    All replaced by the our_data/* pipelines + reproject.py + extract_patches
    in the Romanian pipeline.

scripts/
    Older MeteoSwiss-derived utility scripts. None are wired into the
    active validate_timestep -> train_models pipeline:
      - training_cscs.py            (original training entry point)
      - xi_grad_cam.py              (pre-merge Grad-CAM + Xi prototype)
      - generate_shaply_maps.py     (pre-merge SHAP prototype)
      - check_grad_cam.py
      - plot_predictions.py
      - plot_test_swiss_data.py
      - patch_stitching.py
      - plot_training.py
      - plots_lightning.py
      - mnist_gradient_vs_feature_maps.py
    Active replacements live at the project root:
      - feature_importance_analysis.py replaces xi_grad_cam +
        generate_shaply_maps + check_grad_cam (combined Grad-CAM + Xi +
        SHAP + classical Shapley analysis).
      - evaluate_coalition.py replaces plot_predictions /
        plot_test_swiss_data.
      - data_statistics.py + summarize_lightning_periods.py +
        summarize_mtg.py + summarize_nwcsaf.py +
        summarize_opera_data.py replace plots_lightning + related
        per-product diagnostics.
      - train_models.py replaces training_cscs.

knowledge_distillation/
    Top-level duplicate of the c4dl/ tree from a separate research branch.
    Holds its own copies of every analysis / dataset / feature / model
    module. None of it is imported by anything in the active pipeline; a
    few legacy scripts (e.g. scripts/training_cscs.py) import from it for
    cross-branch comparisons.

Code that is NOT legacy (kept in c4dl/ because the active pipeline imports
it directly)
-------------------------------------------------------------------------

c4dl/projection.py
    GridProjection + romania_grid_area — used by reproject.py,
    identify_patches.py and our_data/lightning_data/read_kml_version2.py
    to define the EPSG:31700 1536x768 target grid for Romania.

c4dl/ml/models/  (only the files listed below)
    Custom Keras layer / loss / metric / optimizer classes that the
    *saved* model checkpoints reference by name. The trained .keras
    files won't deserialise without them, so `feature_importance_analysis.py`
    imports them and feeds them to `tf.keras.models.load_model(...,
    custom_objects=...)`. Specifically:

      - blocks.py    : ConvBlock, ResBlock
      - models.py    : CastLayer, RepeatLayer, iou_metric, dice_metric,
                       true_pos, true_neg, false_pos, false_neg,
                       make_rain_loss_hist, prob_binary_crossentropy,
                       WeightedBinaryCrossentropy, WeightedFocalLoss
      - rnn.py       : ResGRU
      - optimizers.py: AdaBeliefOptimizer
      - layers.py    : ReflectionPadding2D, Warp (transitive dependency
                       of blocks.py and rnn.py)

    train_models.py and evaluate_coalition.py do NOT import these — both
    carry their own self-contained copies of ConvBlock / ResBlock /
    ResGRU / WeightedFocalLoss (with explicit "no c4dl dependency"
    comments). So c4dl.ml.models is load-bearing only for
    feature_importance_analysis.py's checkpoint reload path.

c4dl/features/batch.py
    BatchSequence — transitive dependency pulled in by
    c4dl/ml/models/models.py at import time. Not used directly by any
    active script.

More legacy code that lives in its original location
----------------------------------------------------
(Correction to the earlier draft of this file: the items below were
previously listed as "not legacy" but are not imported by any active
root-level script.)

c4dl/ml/models/attention.py
    Attention-layer building blocks from an earlier architecture
    experiment. Not referenced by anything in the active pipeline
    (feature_importance_analysis.py mentions "attention" only in a
    docstring describing Grad-CAM's spatial attention behaviour).

c4dl/analysis/  (shapley.py, calibration.py, ensemble.py, evaluation.py,
                 parameter.py)
    Loss / metric / Shapley / calibration helpers from the original
    MeteoSwiss analysis pipeline. No active root-level script imports
    them. feature_importance_analysis.py mentions
    c4dl.analysis.shapley.load_scores only in a comment — the actual
    Shapley logic is reimplemented inline in that file. The remaining
    consumers (c4dl.visualization.plots, scripts/plots_lightning.py)
    are themselves legacy.

c4dl/visualization/plots.py
    Plot helpers from the original pipeline. Only consumers are
    c4dl.analysis.evaluation (transitive) and scripts/plots_lightning.py
    (legacy). The active diagnostic plots are produced inline by
    evaluate_coalition.py (training curves, metrics per lead-time,
    reliability, ROC, PR, confusion matrix) and
    feature_importance_analysis.py (Grad-CAM grids, Xi heatmaps,
    Shapley bars, prediction diagnostics).

c4dl/utils.py
    Generic numerical helpers from the original pipeline. Not imported
    by any active root-level script — the helpers active scripts need
    were either inlined or replaced by numpy / scipy primitives.

Removing legacy code
--------------------
Anything outside the "NOT legacy" section above can be deleted at any
time without breaking the active pipeline; the dependencies are
contained. If you do decide to remove c4dl/datasets/msgccs4.py,
remember to delete legacy/process_nwcsaf.py at the same time (msgccs4
is the only remaining consumer).

Cleanup order, if you want to walk this out:

  1. Delete the scripts/ folder (no other active code imports it).
  2. Delete the knowledge_distillation/ folder (no other active code
     imports it).
  3. Delete c4dl/features/test_nc.py and c4dl/features/regions.py
     (only scripts/ uses them).
  4. Delete every file in c4dl/datasets/ — none are imported by the
     active pipeline once steps 1-3 are done.
  5. Delete legacy/ (process_nwcsaf.py is left orphaned once
     c4dl/datasets/msgccs4.py is gone).
  6. Delete c4dl/analysis/, c4dl/visualization/, c4dl/utils.py,
     c4dl/ml/models/attention.py.

After that, c4dl/ contains exactly: projection.py, ml/models/blocks.py,
ml/models/models.py, ml/models/rnn.py, ml/models/optimizers.py,
ml/models/layers.py, features/batch.py — every one of them load-bearing
for the active pipeline.
